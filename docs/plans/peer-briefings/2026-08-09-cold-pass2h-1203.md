## Blocker

### B1 - first-connector TOCTOU: any same-namespace token holder can steal the resume mint

**Evidence:** `hub/src/web/pendingResumePeerMint.ts:9-11,22-49`; `hub/src/socket/handlers/cli/index.ts:100-116`; `hub/src/sync/syncEngine.ts:2801-2822`; `cli/src/modules/pingPeer/pingPeer.ts:545-553`.

**What the tip fixed (verified):**

- `peerSessionTagFd.ts` deleted; `HAPI_PEER_SESSION_TAG_FD` / `peerSessionTag` RPC field gone from runner spawn, `rpcGateway`, `apiMachine`, `rpcTypes`.
- Resume spawn uses `stdio: ['ignore','pipe','pipe']` only — no fd 3 mint pipe (`cli/src/runner/run.ts`).
- `bootstrapExistingSession` no longer consumes a child mint-proof; comment states hub one-shot (`cli/src/agent/sessionFactory.ts:326-329`).
- Create path still tag-gated on `/cli` connect (`peerCapabilityOnConnect.test.ts`); namespace+sessionId alone does not mint when unarmed.
- M1–M4 hold under focused tests (see Verification).

**What is not closed:**

Hub `armResumePeerMint(sessionId)` before `spawnSession`, then `consumeResumePeerMint(sessionId)` on **any** `/cli` socket that names that id in the namespace — no tag, no machine binding, no runner correlation. First connector wins for up to `RESUME_PEER_MINT_TTL_MS` (30s). The module comment admits this residual.

Attack path (practical, not theoretical):

1. Attacker holds the shared namespace CLI token (every wrapped session does).
2. Attacker knows/list victim sessionId (namespace session list).
3. Attacker opens the arm window: `POST /api/sessions/<victim>/resume` is reachable from `ping_peer` when the target is inactive.
4. During arm→real-CLI-connect, attacker connects `/cli` with `auth.sessionId = victim` and **no** `sessionTag`.
5. Hub emits victim `peer-capability`; attacker POSTs `/cli/sessions/<victim>/peer-messages` with that capability → attributed as victim.
6. Legitimate resume CLI connects second → mint already consumed → fail-closed unattributed for the real session.

This is the pass2c B3 outcome with a stopwatch. Compared to the pidfd Blocker pass2g closed:

| Dimension | pidfd tag steal (closed) | first-connector mint steal (open) |
|---|---|---|
| Attacker set | same-UID + `ptrace_scope=0` on victim host | any namespace token holder with hub reach |
| Window | ~1ms startup race | up to 30s; full TTL if spawn fails (no disarm) |
| Trigger | must race child drain | can **cause** arm via resume / `ping_peer` |
| Binding | secret briefly in child | **no** binding to resumed process / machine channel |

RFC § Revision 2026-08-09 kill line: claims must be bound to an authenticated source-session channel; namespace existence is not binding. A race on caller-selected `sessionId` after an unbound hub arm is not that channel. Analogous to an OAuth device-code / missing-PKCE first-consumer race: the one-shot is a bearer for whoever polls first, not proof the connecting CLI is the spawn the hub just ordered.

**Suggested fix:** do not mint on anonymous first connect. Bind the one-shot to the authenticated machine/spawn channel (e.g. return capability on the machine RPC spawn result; runner hands it to the child on a runner-owned path), or arm with `{sessionId, machineId, correlation}` and consume only when the connecting socket proves that correlation. Disarm on spawn failure. Add an adversarial test: session A connects as B during an armed window and must **not** receive B's capability.

Confidence: 95%.

## Friction (steelman)

Opposite case: "30s one-shot is fine; same-namespace already shares the CLI token; documented residual; Ready YES." Kill criterion under Exit 1: forged **attribution** is worse than none, and namespace checks are explicitly non-binding. Sharing a token for hub access is not the same as minting another session's provenance HMAC. If the estate wants to accept first-connector races among namespace peers, amend the RFC / scope-lock in writing — do not ship the comment in `pendingResumePeerMint.ts` as a silent contract change. Cheapest falsification: two same-namespace CLIs; arm B; A connects as B first; A must not get `peer-capability` for B.
